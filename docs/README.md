# Совфрахт Детали (Sovfrasht_Parts) — пакет системной и бизнес-аналитики

Аналитическая база проекта для передачи в разработку (Claude Code). Документы пишутся «по порядку»: от бизнес-слоя к системному, так чтобы каждый следующий артефакт опирался на предыдущий.

- **Продукт (рабочее название):** Совфрахт Детали
- **Репозиторий:** https://github.com/SergeiOrlov88/Sovfrasht_Parts
- **Контекст:** внутренний инструмент компании для распознавания судовых деталей, закупки и оценки ремонта по собственному флоту (в перспективе — расширение на внешних пользователей). На старте — single-tenant, деплой на существующий сервер компании.
- **Деплой:** тот же сервер, где работают «Факт Прочности» и «Пирометрика» (прод и тест). Стек MVP подгоняется под уже используемую инфраструктуру.

## Как мы работаем

Роли: в этой сессии Claude выступает как **бизнес- и системный аналитик** вместе с заказчиком; **Claude Code** — разработчик, который реализует код по этим спецификациям. Чем точнее спецификации, тем меньше переделок на этапе кода.

Процесс: аналитик готовит документ → заказчик ревьюит и правит → документ фиксируется как «утверждён» → Claude Code реализует. Изменения вносятся через версии этого пакета, а не правкой кода напрямую.

## Решение по платформе (зафиксировано)

**MVP — mobile-first PWA. Целевая архитектура — кроссплатформенный натив (Flutter или React Native).**

Обоснование: ядро сценария — съёмка детали в машинном отделении (мобильный контекст), поэтому долгосрочно нужен натив (камера, офлайн-очередь, пуш-уведомления). Но для проверки гипотезы на пилоте (3–5 судов) PWA даёт скорость: нет ревью в сторах, мгновенные обновления, одна кодовая база, камера через браузерный API, базовый офлайн через service worker. Технические решения выбираем так, чтобы миграция на натив не требовала переписывания бизнес-логики (общий бэкенд и API, вынесенная доменная логика).

## Глоссарий (базовый)

**IMPA-код** — шестизначный отраслевой код судовых расходных материалов и запчастей (Marine Stores Guide, International Marine Purchasing Association). Основной ключ для закупки.

**ISSA-код** — альтернативный отраслевой код (International Ship Suppliers & Services Association).

**OEM-номер** — номер детали по каталогу производителя (Wärtsilä, MAN, Alfa Laval и т.д.). Ключ для деталей без IMPA-кода.

**Human-in-the-loop (HITL)** — участие оператора-эксперта в подтверждении спорных распознаваний; на раннем этапе обеспечивает качество и накапливает размеченные данные.

**Confidence (достоверность)** — оценка уверенности системы в результате распознавания; всегда показывается пользователю.

**Ремонт vs замена** — рекомендация: восстановить деталь или заказать новую, с учётом стоимости и простоя.
