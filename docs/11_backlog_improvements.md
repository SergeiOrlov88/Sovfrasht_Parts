# 11 · Беклог улучшений (находки при подготовке демо)

Живой список дефектов и улучшений, найденных после сборки MVP. Ведётся отдельно от исходного бэклога историй (`docs/03`). Каждый пункт: проблема → почему важно → причина → предлагаемое решение → приоритет → связь с требованиями. Реализация — по согласованию, не «молча в коде».

Приоритеты: **P1** — до пилота/важно для восприятия; **P2** — желательно; **P3** — по возможности.

---

## Тема A — Ролевая логика и навигация

### BL-01 · Стартовый экран не зависит от роли — судовладелец видит съёмку, которую не может выполнить · P1
**Проблема.** Пользователь с ролью `fleet_owner` (и, вероятно, `supplier_manager`, `expert`) при входе попадает на экран съёмки. Кнопка «Распознать деталь» у него неактивна, потому что создавать скан по бизнес-правилу может только механик — но кнопки и слоты съёмки ему всё равно показаны.
**Почему важно.** Классический UX-антипаттерн: интерфейс предлагает действие, которое роль не может совершить, и не объясняет почему. Пользователь считает это поломкой (что и произошло). Для внутреннего инструмента это подрывает доверие с первого экрана.
**Причина.** Разграничение доступа реализовано только на сервере (RBAC на `POST /scans`), а фронтенд показывает всем один и тот же «домашний» экран. Нет ролевого лендинга/навигации.
**Решение.** Ввести стартовый экран под роль: механик → съёмка; снабженец/судовладелец → реестр заявок/сканов; эксперт → очередь модерации; админ → админка. Экран съёмки показывать только ролям, которым он доступен.
**Связь:** E4 (роли/права), FR-AUTH-02/03, FR-PRO-06.

### BL-02 · Неактивная главная кнопка без объяснения причины · P2
**Проблема.** Кнопка «Распознать деталь» просто серая, без подсказки, почему нельзя нажать (нет фото? нет прав?).
**Почему важно.** Отключённое действие обязано объяснять причину — иначе пользователь в тупике.
**Решение.** Если действие недоступно по роли — не показывать его вовсе (см. BL-01). Если недоступно по состоянию (нет обязательного кадра) — писать прямо: «Добавьте фото шильдика». Никогда не оставлять «немую» серую кнопку.
**Связь:** NFR-UX (usability), E4.

### BL-03 · Продуктовое решение: кто вправе создавать скан? · P1 (требует решения заказчика)
**Вопрос к владельцу продукта.** Сейчас скан создаёт только механик. Но судовладелец/суперинтендант и инженер верфи тоже бывают на борту и могут фотографировать деталь. Возможно, право съёмки стоит расширить, а не прятать.
**Почему важно.** От этого зависит и навигация (BL-01), и охват сценариев из `docs/02`.
**Решение.** Зафиксировать политику: список ролей, которым доступно создание скана, и обновить `docs/04` (FR-CAP) и `docs/03`. Далее подогнать UI.
**Связь:** FR-CAP-01, 02_personas_scenarios, E4.

### BL-04 · Нет глобальной навигации между разделами · P2
**Проблема.** Между съёмкой, реестром, очередью эксперта, профилем нет единого меню — переходы разрозненны, «открыть по id» осталось как костыль.
**Решение.** Добавить нижнюю/боковую навигацию с разделами по роли. Заменить «открыть по id» настоящим реестром сканов (см. BL-05).
**Связь:** E1 (реестр), 09_ux_screen_map.

## Тема B — UX/UI

### BL-05 · «Открыть скан по id» — дев-артефакт в проде · P1
**Проблема.** Ввод UUID вручную — инструмент разработчика, не пользователя. На демо это уже резануло (обрезанный пользовательский путь).
**Решение.** Реализовать реестр/список сканов (E1): последние сканы с превью, статусом и достоверностью, тап → отчёт. «Открыть по id» убрать из пользовательского интерфейса (оставить максимум в дев-режиме).
**Связь:** E1, FR-REG-01.

### BL-06 · Единые состояния: пусто / загрузка / ошибка · P2
**Проблема.** Разрозненные и «немые» состояния (битые фото на лёгком стенде, отсутствие явных сообщений об ошибке распознавания на UI).
**Решение.** Ввести единый набор состояний: пустой список, идёт распознавание (скелетон/прогресс), ошибка с действием «повторить», нет прав. Согласовать по всем экранам.
**Связь:** NFR-REL-02/03 (отображение ошибок), 09_ux_screen_map.

### BL-07 · Баланс и адаптивность верстки · P2
**Проблема.** На десктопе контент был прижат к краю с пустотой (частично уже правится); нужна цельная сетка и на телефоне, и на широком экране.
**Решение.** Центрированная колонка с max-width, единые отступы/типографика по всем экранам, mobile-first, но аккуратно на десктопе. Ориентир — `Прототип/MarinePartID_Prototype.html` и целевой макет экрана съёмки.
**Связь:** NFR-COMPAT-02, 09_ux_screen_map.

### BL-08 · Живой предпросмотр камеры требует HTTPS · P3 (для пилота — P2)
**Проблема.** `getUserMedia` (рамка-видоискатель) недоступен на HTTP-витрине; работает нативная камера телефона. Для полноценного UX нужен защищённый контекст.
**Решение.** На пилоте выдать витрине домен + TLS-сертификат, включить живой предпросмотр с рамкой и подсказками кадрирования.
**Связь:** NFR-SEC-01, NFR-COMPAT-01.

### BL-09 · Первичная подсказка/онбординг под роль · P3
**Проблема.** Нет короткого пояснения, что делать на первом экране под конкретную роль.
**Решение.** Лёгкий онбординг-хинт: механику — «снимите шильдик крупно», снабженцу — «здесь заявки флота» и т.п.
**Связь:** UX, 02_personas_scenarios.

## Тема C — Каталог и экспертный контур

### BL-10 · Экспертное заведение опознанной детали в каталог · P2
**Проблема.** После разворота на vision-first (ADR-06) деталь опознаётся всегда, но каталог из 57 позиций её обычно не содержит. В отчёте уже есть плашка «в каталоге закупки не найдено» с кнопкой «Отправить эксперту» — однако завести опознанную деталь в каталог эксперту негде: эндпоинта нет. Поток обрывается ровно там, где начинается ценность закупки, а накопленные опознания никуда не конвертируются.

**Решение.** Замкнуть контур: из карточки задачи модерации эксперт заводит новую позицию каталога, предзаполненную опознанием (тип, производитель, модель, маркировка, назначение), проставляет коды IMPA/ISSA/OEM и привязывает скан к созданной позиции. Требуется: эндпоинт создания позиции из результата распознавания; право на заведение позиции (роль `expert`/`admin`, проверка на сервере, NFR-SEC-03); правила заведения — обязательные поля, запрет дублей по коду (уникальность OEM/IMPA), пометка источника «заведено экспертом» для последующего аудита качества.

**Зачем.** Каталог начинает расти сам собой, из реального потока с флота, а не ручным импортом. Это же даёт размеченные примеры для FR-REC-06.

**Связь:** FR-CAT-*, FR-HITL-02/03, ADR-06, docs/01 §5.1, экран отчёта (плашка «нет в каталоге»).
