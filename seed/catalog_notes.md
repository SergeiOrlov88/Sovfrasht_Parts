# Стартовый каталог (seed) — примечания к данным

Файл: `catalog_seed.csv` — курированный стартовый справочник деталей для MVP-категорий **топливная аппаратура** и **насосы**. 56 позиций. Назначение — дать шагу 3 (сопоставление с каталогом, A3) данные для разработки и тестов матчинга, а также наполнить демо.

## Формат (колонки под модель Part, docs/07)

`name, category, maker, impa_code, issa_code, oem_number, equipment, specs, aliases, alt_oem`

- `category` — `fuel_equipment` или `pump`.
- `specs` — JSON-строка. Внутри всегда есть `subtype` (тип детали) и `num_status` — **уровень достоверности номера**.
- `aliases` — синонимы через `;` (для нечёткого поиска и разбора шильдика).
- `alt_oem` — кросс-референсы/аналоги через `;`.

## Уровни достоверности номера (`num_status`)

- **verified (13 позиций)** — OEM-номер подтверждён по открытым каталогам: серии Bosch Common Rail (`0445120xxx`), Denso (`095000-xxxx`), механическая форсунка Yanmar (`719575-53100`). Эти номера реальны и годятся как эталон для проверки матчинга.
- **representative (39)** — номер реалистичен по паттерну вендора, но **не сверен с официальным OEM-каталогом**. Производитель и оборудование достоверны; сам номер перед закупкой обязательно проверять. Часть строк намеренно без номера (`oem_number` пуст) — тогда ключ идентификации это `name + maker + equipment`.
- **generic (4)** — универсальные детали насоса (wear ring, втулка вала, подшипник, прокладка) без единого номенклатурного номера; идентификация по типу и оборудованию.

## Важные оговорки

Коды `impa_code`/`issa_code` в большинстве строк пустые — и это правильно: сложные OEM-спарки (форсунки, ТНВД, элементы насосов) в справочниках IMPA/ISSA, как правило, не кодируются, их ключ — OEM-номер (см. FR-CAT-03, бизнес-правило docs/01). IMPA-коды имеет смысл добавлять для расходных позиций (фильтры, уплотнения-стандарты) при получении лицензионного доступа к Marine Stores Guide.

Это **seed для разработки**, а не верифицированный закупочный справочник. Перед боевым использованием часть `representative`-номеров нужно сверить с OEM-каталогами (Wärtsilä, MAN Energy Solutions, IMO AB и т.д.) — лучше всего по реальным шильдикам с вашего флота.

## Как использовать

Залить сидером в таблицу `parts`. При матчинге (шаг 3): точное совпадение по `oem_number`/кодам → нечёткий поиск pg_trgm по `name`/`oem_number` и `aliases` → top-N кандидатов (закрывает NFR-ACC-02). Поле `alt_oem` можно использовать для наполнения связей `PartAlternative`.

## Расширение

Каталог легко нарастить теми же колонками. Приоритет расширения — по фактическому оборудованию вашего флота: добавить конкретные модели двигателей и насосов, которые реально стоят на судах Совфрахта, и подтянуть под них verified-номера из OEM-каталогов.
